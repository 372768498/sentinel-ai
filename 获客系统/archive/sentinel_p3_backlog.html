原则：没有路线图，只有触发条件。没有 deadline，只有"什么发生了就该做"。

1. CC 验收报告里的遗留

CC 完成 v1 时主动标出来的 known issues，不影响产品上线但要记着。
P2 CC 遗留
ConversationHandler 卡住时的引导提示
当用户在 onboarding 第 3 步（quiet hours 输入）卡住时，如果发了无关消息，bot 只显示"格式错误"，不会主动提示用户"我在等输入，发 /cancel 退出"。

影响：新用户可能困惑，以为产品坏了。
触发条件
用户反馈 onboarding 卡住或退订理由提到"困惑"
预估工时
30 分钟
复杂度
低 · 在每个 ConversationHandler state 加 fallback
P2 CC 遗留
Inline 按钮点击后的显式取消机制
当前 inline 按钮点击进入子流程后没有显式 "取消" 按钮，用户只能等输入合法值或超时（30 分钟）。

影响：UX 不优雅，老用户改 watchlist 时可能困住。
触发条件
和上一条同时修
预估工时
30 分钟
复杂度
低 · 加 ❌ Cancel 按钮到所有 inline keyboard
P2 CC 遗留
Redis 对话上下文持久化
当前对话上下文（onboarding 进度、用户最近收到的告警）存内存，worker 重启会丢。

影响：v1 阶段可接受。但当用户量超过 50 或需要 worker 频繁重启升级时，丢上下文会有不好的体验。
触发条件
≥50 付费用户 OR worker 部署到云端开始频繁更新
预估工时
2-3 小时
复杂度
中 · Redis + Pickle Persistence
P3 CC 遗留
yfinance ticker 验证缓存
Onboarding 验证 5 个 ticker 当前需 3-5 秒（并行 fast_info 请求）。

影响：用户体验稍微卡顿，但 onboarding 一辈子才走一次，影响小。
触发条件
用户反馈 onboarding 慢，OR yfinance 出现限流
预估工时
30 分钟
复杂度
低 · 加 Redis 缓存层

2. 推送优先级 + Critical Alerts

2026.05.07 对话讨论的"波动巨大时打电话"方向。结论：现在不上电话，但要在数据结构里预留位置。
P1 产品想法
推送 priority 字段
在 templates/telegram_messages.py 给每个推送加 priority 字段（normal / urgent / critical）和 disable_notification 控制。

三个级别：
  • normal：普通 threshold 越线，默认推送
  • urgent：>5% 单股暴跌、SEC 调查、退市公告等 → disable_notification=False + 自定义提示音
  • critical：VIX spike >50%、Fed 紧急加息、系统性风险 → 预留字段 should_call=true，未来接 Twilio
为什么 P1：不实现真电话，但数据结构要现在定。等真要做时不用改模板。
触发条件
下次 CC 改 templates 时顺手加
预估工时
15 分钟
复杂度
极低 · 改 dict 结构
P3 产品想法
Twilio 电话告警（"Pro Plus" tier）
真实电话告警，用 Twilio API 拨打 + 文本转语音，不用 Telegram VoIP（违反 ToS）。

触发场景候选：
  • 个股单分钟跳水 >5%（fat finger / 黑天鹅）
  • 持仓股票 SEC 调查 / 退市公告
  • Fed 紧急加息 / 系统性风险
  • VIX 单日 spike >50%
定价构想："Pro Plus" $79/month，包含电话告警 + 优先客服。

成本：Twilio $0.013/min，30 秒告警 = $0.0065，毛利充足。

为什么 P3：需要 50+ 付费用户才有意义。早做是过度工程。
触发条件
≥50 付费用户 + 至少 3 人主动询问"能不能打电话"
预估工时
1-2 天
复杂度
中 · Twilio 集成 + 用户手机号管理 + 计费
P3 产品想法
Critical Alerts 路线图卖点
更新 Whop description 时加一行未来承诺：

"Critical Alerts (coming Q3): When something truly market-moving hits your watchlist (>5% single-stock plunge, systemic risk events), Sentinel can phone you directly. Your call to enable."

目的：给产品的"严肃性"建立期待。让访客觉得这不是又一个 signal group，是真把客户当回事的服务。
触发条件
下次更新 Whop description 时（可能 v6 视频上线时）
预估工时
5 分钟
复杂度
极低 · 复制粘贴

3. 用户输入交互升级

v1 用了对话式表单，跑通后用户体验不错。但当用户量起来后可以考虑升级。
P3 产品想法
Telegram Mini App / Web App
v2/v3 版本可以考虑做一个 Telegram Mini App：
  • 真实的 watchlist 编辑器（搜索股票、批量增删、设阈值）
  • 历史告警查看器（看过去 30 天的所有推送）
  • 统计 dashboard（你的告警精度、平均响应时间）
为什么 P3：需要做独立 web app + 服务器托管 + HMAC 验证，工作量大。当前对话式表单 + /watchlist dashboard 已经够用。

什么时候做：用户反馈"watchlist 太多看不过来" OR "想看历史告警分析" 时再考虑。
触发条件
≥3 个用户主动要求 OR 用户平均 watchlist >15 个 ticker
预估工时
1 周
复杂度
高 · 全栈 web app + Telegram initData 验证
P3 产品想法
双向交互接 LLM
当前 "What about TSLA?" 走规则路由 + 模板回复。如果未来用户问得越来越复杂（"为什么 NVDA 今天涨这么多" / "我应该担心什么" / "这家公司 CFO 是谁"），可以接 LLM 做自然语言回答。

必须的约束（system prompt）：
  • 永远不能给 buy/sell 建议（红线）
  • 必须 cite source URL
  • 不预测股价，只解释当前状态
可复用：OpenClawd / Anthropic 的 agent 配置已有，迁移时复用 system prompt 设计。
触发条件
用户反问中 ≥30% 是规则路由覆盖不到的复杂问题
预估工时
3-4 小时
复杂度
中 · 已经预留了 LLM 槽，主要是 prompt 工程 + cost 控制

4. 内容自动化

公开频道 14 天测试期间手工把关，跑稳后某些内容可以自动化。
P2 产品想法
Live caught moment 全自动化
当前盘中 caught moment（earnings beat / Fed surprise / SEC filing）是定时 brief / digest 自动发，但实时事件推送到公开频道这步先人工把关，避免 AI 判断错或源链接挂了砸品牌。

什么时候自动化：跑 14 天后，如果手工把关过的所有 caught moment 都质量稳定、源链接 100% 可用、AI 提取 catalyst 没出过错 → 可以放开自动化。
触发条件
14 天测试期间手工把关 ≥10 条 caught moment 都准确
预估工时
2 小时
复杂度
中 · 加 confidence threshold 判断逻辑
P3 产品想法
/api/bot/push-alert 内部接口
CC 在验收报告里建议的"Live caught moment 工具"：给一个内部 API，你人工填好数据后触发，bot 自动发给所有关注该 ticker 的用户。

用途：14 天公测期间手工运营，逐步沉淀质量数据。
触发条件
公测期间发现需要快速 broadcast 而不靠定时
预估工时
30 分钟
复杂度
低 · 加一个 FastAPI endpoint + 鉴权

P2 运营事项
首批 5 付费用户手动获客
找首批 5 个真实付费用户，验证产品/市场契合度。

渠道候选：

后端云端部署
当前 worker 跑在你 Windows 本地 + Docker Postgres。电脑关机 = 服务挂掉。

触发条件：≥5 付费用户后必须上云。

选项：Railway / Fly.io / Render 都能跑 Python + Postgres，月费 $5-20。
触发条件
≥5 付费用户

P3 运营事项
数据源接入升级（替代 yfinance）
当前主要用 yfinance（免费但限流，偶尔 fast_info 失败）。如果用户量起来 / 越线告警频次提高，需要更稳定的数据源。

候选：
  • Polygon.io：$29/月起，实时数据，专业级
  • Alpaca：免费 + 有 paper trading API
  • Alpha Vantage：免费 tier 25 calls/day，付费 tier $49/月
对应 SEC EDGAR / Reuters / Bloomberg 信源：需要 Reuters Connect API 等更专业接入，目前由 OpenClawd 处理。
触发条件
yfinance 失败率 >5% OR 用户量 ≥30
预估工时
1-2 天
复杂度
中 · API 切换 + 计费监控

6. 长期方向（可能永远不做）

长期参考项。每隔几个月看一次，可能某天某条会变得相关。
P3 产品想法
TikTok / Reels / X 短视频矩阵
9:16 / 1:1 比例的短视频系列，做"caught moment"故事讲述（"用户 A 在睡觉，Sentinel 抓住了 NVDA 的 6% 跳水"）。

触发条件：找到首批 5+ 付费用户，他们的真实 caught moment 案例可以授权使用 → 做成短视频。
触发条件
5+ 付费用户 + 至少 3 个真实可授权案例
预估工时
每条 2-3 小时
复杂度
中 · Remotion 模板批量产出
P3 产品想法
多语言版本（中文 / 日文）
当前全英文，面向美股用户。但中国 / 日本投资美股的散户也很多。

不急的原因：
  • 当前 ICP 是英语 native 用户
  • 多语言会拖慢内容运营节奏
  • 需要新建 Telegram channel + 重写文案 + 维护多个版本
什么时候做：当中文/日文用户主动询问 ≥10 次时。
触发条件
≥10 个非英语用户主动询问
预估工时
3-5 天
复杂度
高 · 文案 + 频道 + bot 多语言架构
P3 产品想法
Sentinel API（让用户接到自己的工作流）
某些用户可能想把 Sentinel 告警接到自己的 Slack / Discord / 邮件 / IFTTT。

提供一个 webhook 接口，每次推送同步发到用户配置的 URL。

触发条件：有用户主动要求"能不能把告警推到我的 Slack"。
触发条件
≥3 个用户要求 webhook / API 集成
预估工时
1 天
复杂度
中 · API 设计 + 鉴权 + 文档
P3 产品想法
机构 / 团队版本（多人共享 watchlist）
小型对冲基金 / 家族办公室可能想给团队共享一个 watchlist，每个人都收 Sentinel 告警。

定价构想："Team" $199/month，5 个用户共享 watchlist，付费给 PI 而不是按人头。

不急的原因：个人 SaaS 是当前 ICP，团队是另一个产品 motion。
触发条件
至少 2 个机构用户主动询问
预估工时
3-5 天
复杂度
高 · 多用户管理 + 计费 + 权限
