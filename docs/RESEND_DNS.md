# Resend DNS Checklist

Sentinel AI only sends email today, so the minimum sending setup is:

1. Verify a dedicated sending subdomain such as `updates.example.com`.
2. Publish the exact SPF, DKIM, and MX records generated by Resend for that subdomain.
3. Use `RESEND_FROM_EMAIL` on that verified domain, for example `Sentinel AI <briefing@updates.example.com>`.
4. Optionally add DMARC after SPF and DKIM are passing.

## Recommended Setup

- Prefer a subdomain instead of the root domain so operational mail reputation stays isolated.
- Do not point Resend receiving MX records at a domain that already handles your real inbox unless you intentionally want Resend inbound mail there.
- If your DNS provider auto-appends the zone name to MX targets, add the trailing dot shown in Resend to avoid malformed records.
- Keep `RESEND_FROM_EMAIL` aligned with the verified sending domain.

## What To Check Before Production

1. In Resend dashboard, the domain status should be verified for sending.
2. SPF and DKIM should both be passing.
3. If you enabled receiving, make sure the MX priority does not conflict with your main mailbox provider.
4. Update Vercel and Railway `RESEND_FROM_EMAIL` to the same verified sender.
